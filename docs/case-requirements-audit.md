# Проверка требований HackAlem — 23 сентября 2026

Проверена текущая рабочая версия после `607d6f9`, исходные файлы организаторов и [полное ТЗ](project_description.md). Это проверка реализации и запуска на текущем Mac; она не заменяет оценку жюри или живую презентацию.

## Вход, результаты и загрузка CSV

```text
data/nodes.parquet + edges.parquet + transactions.parquet
                         ↓
                    python main.py
                         ↓
results/nodes_roles.csv + clusters.csv + top_nodes.csv
                         ↓
CSV + исходные nodes/edges → основной граф приложения
```

`starter/starter.py` создаёт шаблоны, что прямо указано в [starter/README.md](../starter/README.md). В проверенном `starter/out/`: 2 248 строк узлов с пустыми ролями/обоснованиями, нулевыми оценками и `cluster_id=-1`; файлы кластеров и топ-листа содержат только заголовки. Их не нужно загружать в приложение или сдавать как готовые результаты.

Дополнительный экран **«CSV переводов»** принимает одну таблицу переводов или агрегированных связей. Он не вычисляет обязательные роли, приоритеты и сообщества. Даже три итоговых CSV не содержат исходных направленных рёбер. Таблица транзакций содержит 2 229 участников; ещё 19 изолированных seed-клиентов и признаки глубины/seed сохраняются благодаря `nodes.parquet`.

Основной сценарий соответствует формату задания. Замена основного сценария одним CSV-дашбордом требованиям не соответствовала бы. Требования загрузить три Parquet или три результата через браузер в ТЗ нет: допускается локальный пайплайн и отдельный экран просмотра.

## Ограничения и обязательные артефакты

| Пункт | Проверенный статус |

| Граница depth=4 | Ни один узел depth=4 не назначен terminal; ограничение видно в карточке. Retention исключён из вклада consolidator на этой границе. |
| Неполные seed-входящие и наблюдаемые суммы | Предупреждения присутствуют; суммы не названы полным балансом. Все 81 seed сохранены, включая 19 без рёбер. |
| Направление, циклы, точные GID | Все 3 119 направленных рёбер сохранены; нет предположения DAG. GID передаются строками; потери точности не обнаружено. |
| Осторожные объяснения | Роли описаны как наблюдаемые признаки/гипотезы; evidence формируется детерминированно из метрик. |
| Локальная инфраструктура | `main.py` не требует OpenAI, API-сервера, frontend, GPU, базы данных или облака. После установки зависимостей расчёт работает локально. Первая установка требует доступных пакетов/кеша. |

| Схема решения | В README есть Mermaid-диаграмма от Parquet через аналитику к CSV/JSON и интерфейсу. |
| Живое пятиминутное демо с 2–3 узлами | Сценарий описан в README; отдельные действия проверены. **Человеческая репетиция и презентация жюри не выполнены этой автоматической проверкой.** |

Опциональные календарные признаки, ограниченная проверка устойчивости top-50, JSON-карточки, backend API и инструменты исследования реализованы. Это не означает, что все опциональные возможности раздела 8 ТЗ полностью доступны в браузере: отдельный интерфейс анализа повторяющихся маршрутов/дробления не проверен, а инструменты веб-чата уже, чем у Python Investigator. Live-запросы с финансовыми фактами в этом аудите не выполнялись.

## Оставшиеся границы интерфейса

Основной `project`-режим работает с реальными CSV и исходными узлами/рёбрами. В карточки пока не импортированы `seed_reach_count`, альтернативные role scores, priority components и рекомендации из богатого `results/node_cards.json`. Для защиты формул используйте `python apps/backend/explore.py explain <gid>` в подготовленном окружении.

Опциональный frontend API-режим ещё требует согласования с фактическим FastAPI-контрактом: отличаются формы поиска, карточек и метаданных подграфа. Для жюри используйте проверенный запуск `python3 scripts/run-local.py`, который выбирает `project` явно. Эти ограничения не заменены фиктивными данными и не скрыты за успешными тестами CLI.
