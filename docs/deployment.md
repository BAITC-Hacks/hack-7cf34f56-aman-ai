# Локальный Docker и размещение на Render

Для жюри подготовлены два пути: локальный контейнер с автоматической установкой зависимостей и защищённая паролем ссылка Render на тот же интерфейс с данными проекта. Аналитика и граф работают без AI. Развёрнутая ссылка ещё не создана; порядок публикации описан ниже.

## Запуск для жюри через Docker

Нужен установленный и запущенный Docker Engine с Docker Compose v2, например Docker Desktop. Python и Node на компьютере жюри не нужны. Первая сборка загружает базовые образы и зависимости из интернета. Из корня репозитория:

```bash
docker compose up --build
```

Откройте **http://localhost:8080**. Сервис `moneygraph` из [docker-compose.yml](../docker-compose.yml) публикует порт только на `127.0.0.1`, поэтому локально пароль не запрашивается. Переменные и ключи из корневого `.env` внутрь контейнера не передаются; AI по умолчанию выключен.

[Dockerfile](../Dockerfile) устанавливает Python- и npm-зависимости, дважды запускает `main.py`, проверяет побайтовое совпадение трёх обязательных CSV и ограничивает каждый пересчёт пятью минутами. Затем готовит данные интерфейса, выполняет включённые проверки и собирает frontend. В итоговом образе остаются Node, production-сборка, сервер и три CSV; Python и исходные Parquet нужны только при сборке. Чистый запуск не использует заранее подготовленные `results/`, локальную `.venv` или `node_modules`.

Ожидаемые результаты набора: 2 248 узлов, 3 119 направленных рёбер, 4 840 транзакций, 81 исходный клиент, 65 сообществ и топ-20. Весь процесс сборки может занять больше пяти минут: лимит задания относится к аналитическому пересчёту, а не к загрузке образов, установке пакетов и frontend-проверкам.

В другом терминале можно проверить состояние и извлечь обязательные CSV:

```bash
docker compose ps
mkdir results/docker && docker compose cp moneygraph:/app/results/. results/docker/
```

Копирование создаёт **новую** папку `results/docker/` с `nodes_roles.csv`, `clusters.csv` и `top_nodes.csv`. Исходные `results/*.csv` не перезаписываются. Если `results/docker` уже существует, `mkdir` остановит команду: выберите другое новое имя папки и замените его в обеих частях команды. Скопируйте результаты до удаления контейнера. Команда использует стандартный [Docker Compose cp](https://docs.docker.com/reference/cli/docker/compose/cp/).

Для остановки нажмите `Ctrl+C`, затем:

```bash
docker compose down
```

Для повторного запуска уже собранного образа достаточно `docker compose up`. При изменении исходников или данных снова используйте `--build`. Без Docker доступен [запуск с Python и Node](../README.md#быстрый-запуск-для-организаторов).

## Render: защищённая ссылка для организаторов

Нужны учётная запись Render и право подключить GitHub-репозиторий **`BAITC-Hacks/hack-7cf34f56-aman-ai`**. Если репозиторий не виден в Render, владелец организации должен разрешить Render GitHub App доступ к нему. Менять видимость репозитория для этого не требуется.

1. Убедитесь, что `Dockerfile`, `docker-compose.yml`, `render.yaml` и production-сервер находятся в ветке `main` на GitHub.
2. В Render Dashboard выберите **New → Blueprint**, подключите репозиторий, выберите ветку **main** и файл **render.yaml** в корне.
3. Проверьте предлагаемые настройки: один **Web Service**, runtime **Docker**, план **Free**, health check **`/healthz`**, порт `10000`. Создавать базу данных или диск не нужно.
4. Запустите **Deploy Blueprint**. Образ пересчитает аналитику и соберёт приложение. Дождитесь успешной сборки и состояния сервиса Live.
5. В разделе Environment сервиса найдите `APP_ACCESS_USER=judge` и созданный Render `APP_ACCESS_PASSWORD`. Передайте организаторам HTTPS-ссылку из Dashboard и эти данные входа через отдельный приватный канал. Пароль не сохраняйте в репозитории или URL.
6. Откройте ссылку в приватном окне браузера: сначала должен появиться запрос логина и пароля, после входа — граф с меткой **«Данные проекта»**. `/healthz` доступен без входа и возвращает только статус; страница, данные и AI-маршруты защищены.

Эти действия соответствуют [официальному процессу Render Blueprint](https://render.com/docs/infrastructure-as-code). Сгенерированный пароль задан через `generateValue` в [render.yaml](../render.yaml); значение не зашито в образ. На хостинге сохраняйте режим доступа `password` — это значение по умолчанию. **Не устанавливайте `APP_ACCESS_MODE=public` для ссылки с реальными данными проекта.**

В конфигурации сервиса стоит `autoDeployTrigger: "off"`: обновление кода запускается через **Manual Deploy → Deploy latest commit**. Автоматическая синхронизация Blueprint — отдельная настройка: чтобы изменения `render.yaml` тоже применялись вручную, установите **Blueprint Settings → Auto Sync → No**, затем используйте **Manual Sync**. [Blueprint deployment settings](https://render.com/docs/blueprint-spec), [управление синхронизацией](https://render.com/docs/infrastructure-as-code#disabling-automatic-sync).

Render Free засыпает после 15 минут без входящего трафика; следующий запрос запускает сервис примерно за минуту. Откройте ссылку перед демонстрацией и дождитесь загрузки. Доступно 750 часов работы бесплатных экземпляров на workspace в месяц; файловая система временная. Расчётные данные включены в образ и восстанавливаются вместе с ним после старта. [Ограничения бесплатного плана](https://render.com/docs/free).

## AI и переменные production-сервера

Без `OPENAI_API_KEY` граф, карточки и CSV доступны, а чат сообщает, что AI не настроен. Для включения добавьте ключ **в Environment сервиса Render**; не передавайте его через чат, `VITE_*`, Docker build arguments или исходный код. Модель по умолчанию — `gpt-4.1-mini`, переопределение — `OPENAI_MODEL`. Использование OpenAI оплачивается отдельно от бесплатного хостинга.

| Переменная | Поведение |
| --- | --- |
| `APP_ACCESS_MODE` | По умолчанию `password`. В локальном Compose явно задан `public`, при этом порт ограничен loopback. |
| `APP_ACCESS_USER` | По умолчанию `judge`. |
| `APP_ACCESS_PASSWORD` | Обязателен в режиме `password`, минимум 16 символов; Blueprint генерирует значение. |
| `APP_ORIGIN` | Разрешённый origin для браузерных AI-запросов. Если не задан, используется `RENDER_EXTERNAL_URL`. Для собственного домена задайте его точный HTTPS-origin, например `https://moneygraph.example.org`. |
| `AGENT_REQUESTS_PER_HOUR` | По умолчанию 20 запросов к чату за часовое окно, общее для всех пользователей одного процесса; допустимо 1–500. |
| `OPENAI_API_KEY` | Опциональный серверный ключ; отсутствие отключает AI. |
| `OPENAI_MODEL` | Модель чата, по умолчанию `gpt-4.1-mini`. |
| `HOST`, `PORT` | Адрес прослушивания; Render использует `0.0.0.0` и `10000`, контейнер Compose — `0.0.0.0` и `3000`. |

Часовой лимит AI хранится в памяти и сбрасывается при рестарте/пробуждении процесса. Он ограничивает число запросов приложения, **но не является жёстким пределом расходов**: один вопрос может вызвать несколько обращений к модели. При достижении лимита чат отвечает 429, граф продолжает работать.

Production-сервер **не читает `.env`**. Он принимает только окружение процесса. `.env` используется командами разработки `dev`/`preview` и отдельным локальным `agent`. Docker Compose передаёт только перечисленные в YAML переменные; наличие ключа в локальном `.env` само по себе не включает контейнерный AI.

Режим данных записывается при сборке в `dist/runtime-config.json`. Runtime использует именно его; конфликтующий `VITE_DATA_MODE` останавливает запуск. После изменения режима данных нужно пересобрать интерфейс. Production-сервер поддерживает `project` и `demo`; Docker собирает `project`.

## Проверка production-сервера без Docker

После подготовки Python-зависимостей, CSV и frontend-зависимостей из корня проекта:

```bash
npm --prefix apps/frontend run build
npm --prefix apps/frontend run test:server
APP_ACCESS_MODE=public HOST=127.0.0.1 PORT=8080 npm --prefix apps/frontend start
```

Это локальный запуск на **http://127.0.0.1:8080**. Для режима с паролем передайте `APP_ACCESS_PASSWORD` через окружение процесса и оставьте `APP_ACCESS_MODE=password`. Команда `npm start` не запускает `main.py`, не пересобирает UI и не подхватывает корневой `.env`.

## Почему выбран Render

Для текущего проекта Render сохраняет обычный Node-сервер и один origin для страницы и AI; Docker задаёт Python на этапе сборки и Node во время работы. Это требует меньше изменений текущего приложения, чем перенос серверного обработчика в функции другого провайдера.

| Бесплатный вариант | Проверенные ограничения и пригодность |
| --- | --- |
| **Render Web Service** | Docker, 512 МБ RAM / 0,1 CPU; задержка пробуждения после простоя. Подходит для выбранного единого сервера и заранее рассчитанных данных. [Docker](https://render.com/docs/docker), [планы ресурсов](https://render.com/docs/compute-plans), [бесплатные лимиты](https://render.com/docs/free). |
| **Vercel Hobby** | Только личное некоммерческое использование. Приватные репозитории GitHub-организаций не поддерживаются на Hobby; общая страница лимитов формулирует ограничение подключения организаций шире. Понадобится адаптация AI-обработчика к функциям и проверка доступа к репозиторию. [Hobby](https://vercel.com/docs/plans/hobby), [Git](https://vercel.com/docs/git#using-hobby-teams), [лимиты подключений](https://vercel.com/docs/limits#connecting-a-project-to-a-git-repository). |
| **Cloudflare Pages / Workers** | Статические запросы бесплатны; Pages — 500 сборок/месяц и 25 МиБ на файл. Functions используют Workers: 100 000 запросов/день и 10 мс CPU на запрос. Статика подходит, но серверному AI нужны адаптация и проверка времени обработки JSON. [Pages](https://developers.cloudflare.com/pages/platform/limits/), [статические запросы](https://developers.cloudflare.com/pages/functions/pricing/), [Workers](https://developers.cloudflare.com/workers/platform/limits/). |

## Что проверено и что осталось

Production-сервер проверен локально на **http://127.0.0.1:5184** с источником `project`. В этом проверочном проходе:

| Проверка | Результат |
| --- | --- |
| Frontend lint и production build | Пройдены |
| Frontend-тесты | 119 пройдено |
| Тесты серверного AI с подставными ответами | 12 пройдено |
| HTTP-тесты production-сервера | 7 пройдено |
| Backend-тесты | 57 пройдено |
| Браузерные сценарии через Playwright MCP | 67 проверок проекта и 30 проверок CSV пройдены; проверены 1440×900 и мобильный экран, неожиданных ошибок нет |
| Отдельная проверка защищённого production через Playwright MCP | Без входа JSON проекта недоступен; после входа работают полный граф и CSV worker; состояние AI без ключа отображается корректно |
| Схемы Render Blueprint и Docker Compose | Конфигурации прошли проверку по схемам |

Живые запросы к AI с финансовыми данными в этом проходе не выполнялись; тесты AI использовали подставные ответы либо состояние без ключа.

В текущей рабочей среде Docker Engine/CLI отсутствует, поэтому **сборка образа, `docker compose up` и копирование CSV из контейнера здесь не выполнялись**. Проверки Node production-сервера и обычной frontend-сборки не заменяют проверку контейнера. Успешное размещение на Render также ещё не подтверждено; фактической hosted-ссылки пока нет.

Для завершения публикации нужен доступ к Render-аккаунту, право подключить указанный репозиторий и выполнение Blueprint deploy. После него нужно проверить HTTPS, вход под `judge`, граф, поиск GID и CSV; AI проверяется отдельно после добавления серверного ключа. До успешного запуска на Render не следует отмечать hosted-версию как готовую.
